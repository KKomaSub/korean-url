# 글길

한국어 문장으로 URL을 표현하는 무상태(Stateless) 주소 변환기. **Cloudflare Pages Functions**를 사용하며 데이터베이스, KV, Durable Objects 없이 작동합니다.

## 배포

Cloudflare Dashboard → Workers & Pages → Create Pages → Connect to Git → `KKomaSub/korean-url`의 `main` 선택.

- Framework preset: None
- Build command: 비워 둠
- Build output directory: `/` (repository root)
- Functions: `functions/` 자동 인식

## 구조

- `index.html`: 원고지와 한지 질감의 웹 화면
- `functions/api.js`: `POST /api` URL 변환 (서버 측, 신형 v3)
- `functions/[slug].js`: `GET /한글문장` v3/v2 URL 복원 및 HTTP 302 (서버 측)
- `functions/글길/[[path]].js`: `GET /글길/문장...` URL 복원 및 HTTP 302 (서버 측)
- `src/words.js`: 제공 CSV에서 품사 기준으로 검증하여 선정한 고정 사전. 배열 순서 변경 금지
- `src/codec.js`: 과거 경로 호환용 v1 코덱 (배포 뒤 사전 순서를 수정하지 말 것)
- `src/words-v2.js`: 업로드된 CSV의 2음절 명사 4,096개 (고정 프로토콜)
- `src/codec-v2.js`: 한 문장 코덱, 52비트/절, CRC32, 선택적 deflate
- `tests/codec.test.js`: 왕복 복원 및 오류 검사

`npm test`로 Node.js 22+에서 코덱을 검사할 수 있습니다.

## 설계 및 제한

신규 주소는 `[명사]의[명사]이/가[명사]의[명사]을/를[동사]` 절을 연결하고, 마지막 절에서 종결형으로 끝나는 한 문장입니다. 한 절에는 52비트가 담기고 경로에는 하이픈, 공백, 쉼표가 들어가지 않습니다. **기존 `/글길/...` 링크는 종전 규칙으로 유지됩니다.** 과거 v1은 `[관형형 형용사]-[주격 명사]-[관형형 형용사]-[목적격 명사]-[동사]` 형태입니다. 형용사·동사는 CSV에서 품사를 검증했고 활용형은 한국어 문법에 맞게 변환합니다. 이전 v1의 각 문장에는 28비트가 담겨 있었습니다. v2는 절당 52비트를 담아 길이를 줄입니다. 프레임에는 버전, 압축 모드, 본문 길이, URL, 체크섬이 포함되어 있어 **저장소 조회 없이 복원**합니다. URL 길이 제한은 4096 UTF-8 바이트입니다. 원본이 길거나 압축률이 낮으면 생성 주소가 오히려 길어질 수 있습니다. 복원 가능하게 하려면 사전과 문장 규칙을 고정해야 합니다.

외부 링크로 이동하는 공개 리다이렉트 서비스입니다. 스팸·피싱을 막기 위한 도메인 차단이나 위험 URL 판정은 별도 운영 정책이 필요합니다.

한글 도메인/경로를 포함한 URL 및 프로토콜을 생략한 `example.com/path` 입력을 지원합니다. 신형 한글 주소는 오로지 완성형 한글 음절로만 이루어진 단일 경로 조각입니다. 입력의 특성에 따라 줄어드는 비율이 다르며, 임의의 URL을 저장소 없이 고정 길이로 압축할 수는 없습니다.

Cloudflare에는 요청 URI 길이 제한이 있어, 생성된 링크를 URL 인코딩했을 때 14,500자를 넘으면 서버에서 오류를 반환합니다. 긴 입력이라도 압축률이 높으면 지원됩니다. 아주 긴 비압축 URL은 DB 없는 한글 단일 경로 방식으로 모든 것을 지원할 수 없습니다.


## v3: 한글과 대한민국 역사·산업 문장

신규 링크는 v3로 발급합니다. 과거 v2 및 `/글길/` v1 링크는 기존 복원기로 계속 동작합니다.

- `src/words-v3.js`: 제공된 CSV에서 검증한 주제어 256개·일반 명사 512개. 한글날, 세종대왕, 훈민정음, 조선, 대한민국, 반도체 등 역사·문화·과학·산업·미래·긍정적 어휘 중심
- `src/codec-v3.js`: 절마다 주제어 8비트·명사 9비트 세 개·동사 4비트로 총 39비트를 담으며, 긍정적인 짧은 동사를 사용하고 가능한 경우 역사적인 마무리 구절 사용
- 원본 URL은 흔한 도메인·URL 문자 토큰 압축, 7비트 인코딩, Unicode/Punycode 복원, 선택적 deflate로 저장소 없이 가역 변환
- `src/idn.js`: 글길 사이트 도메인이 한글일 때 복사되는 주소의 호스트 이름에 Punycode 대신 한글 표기 사용
- 생성 경로에는 공백·숫자·특수문자가 없으며 한글의 연속 문장으로 구성. 모든 명사의 임의 조합이 완전히 자연스러운 문장을 만드는 것은 아님
- v3 사전의 순서와 문장 규칙을 바꾸면 과거 링크가 복원되지 않으므로 **절대 변경 금지**

실행: `npm test` (Node.js 22 이상). 데이터베이스·KV·R2 없음. 장문 URL은 길이 제한에 걸릴 수 있으며 입력의 내용에 따라 새 주소가 오히려 길어질 수도 있습니다.


## v4 — 연관 개념망 기반 문장

- **DB·KV·외부 서버 없이** 모든 URL 정보를 경로 안에 넣어 복원합니다.
- 한국사·한글·문화·과학·산업·민주주의·자연·미래의 8가지 **중첩 주제 관계망**을 사용합니다. 주제어 → 주어 → 두 관련 개념 → 동사로 이어지는 어휘는 앞선 단어와 이전 절의 맥락에 따라 달라집니다. 복원 시에도 동일한 관계망을 역으로 순회합니다.
- 조사 `이/가`, `과/와`, `을/를`을 받침에 따라 선택하고 연결형 동사는 `~고`, 종결형은 `~다` 등을 사용합니다.
- 마지막에 남은 데이터량이 적으면 `문화가빛난다`, `지혜가미래를잇다` 같은 가변 길이 종결 절을 사용합니다.
- URL 전용 6비트 문자 압축, 7비트 접두 사전, 일반 deflate 및 자주 쓰는 도메인의 고정 호스트 사전 중 가장 짧은 표현을 택합니다. 고정 호스트 사전은 코드 안의 변하지 않는 압축표이며 링크별 매핑을 저장하는 DB가 아닙니다.
- **v1~v3은 영구 복원 가능하도록 기존 코드를 그대로 유지합니다.** v4 생성 링크는 코드 `src/semantic-graph.js`의 사전/순서를 변경하면 복원되지 않으므로 수정하지 마세요.

주의: 관련 분야를 선택하는 규칙은 단어의 문법 및 주제 일관성을 개선하지만 자연어 의미를 완벽하게 보장하는 언어 모델은 아닙니다. 정보를 잃지 않고 임의 길이의 URL을 저장 없이 원래대로 복원하려면 경로에 필요한 비트 수를 담아야 하므로 모든 URL의 길이를 무조건 줄일 수는 없습니다.

## 문장의 뜻 풀이 — Gemini + D1 (R2 사용 안 함)

한글 URL을 생성하는 기본 경로는 종전대로 데이터베이스가 없습니다. 생성한 문장의 **뜻 풀이에만 D1**을 사용합니다. 기본 화면은 문장의 실제 단어·동사·주제 흐름을 바탕으로 한 규칙 풀이를 보여 주며, **AI 뜻풀이 버튼을 누른 경우에만** Gemini에 요청합니다. 코드화한 주소에 숨겨진 진짜 역사적 메시지가 있는 것은 아니며 **문학적 해석**입니다.

### 처음 설정 (Cloudflare Pages)

1. Cloudflare → Workers & Pages → D1 → 새 데이터베이스 `korean-url-meaning` 생성.
2. SQL Console에 `migrations/0001_meaning.sql` 파일 전체를 실행합니다. (또는 `wrangler d1 execute korean-url-meaning --remote --file=migrations/0001_meaning.sql`)
3. Pages 프로젝트 → **Settings → Bindings → Add → D1 database**에서 `MEANING_DB`라는 이름으로 위 D1을 연결합니다. 미리보기 환경도 쓴다면 거기에도 바인딩합니다.
4. Pages 프로젝트 → **Settings → Variables and Secrets**에 아래 값을 설정한 뒤 다시 배포합니다.

| 변수 | 값 | 설명 |
| --- | --- | --- |
| `GEMINI_API_KEYS` | `KEY1,KEY2,...` | Secret; 쉼표로 구분, 순서대로 장애 전환. 절대 코드에 포함하지 않습니다. |
| `GEMINI_DAILY_PER_DEVICE` | `5` | 한국 시간 기준 브라우저 지문당 매일 AI 호출 가능 횟수 (0~1000). 규칙 풀이와 캐시 응답은 미차감. |
| `FINGERPRINT_HASH_SALT` | 임의의 길고 무작위인 비밀 문자열 | 필수 Secret. 브라우저 지문 해시를 서버에서 다시 익명화합니다. 최소 12자. |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | 신규 프로젝트 기본 모델. 실제 무료 할당량은 Google 정책을 확인해야 합니다. |
| `QUOTA_TIMEZONE` | `Asia/Seoul` | 기본 일일 집계 기준, 생략 가능. |
| `KOREAN_DICT_API_KEY` | (선택) | 표준국어대사전 API 키. 네이버 사전 요청 실패 시 대안. |

- 같은 변환 문장(따라서 같은 정규화 원본 URL)은 SHA-256 해시를 키로 D1에서 **Gemini 설명 1회만 저장**하고, 이후 AI 호출 없이 답합니다. 일일 한도 초과 후에도 캐시 조회는 무료입니다.
- `device_usage`는 사이트별 브라우저 지문을 서버 비밀 salt와 함께 해시한 값을 날짜별로 저장합니다. 동시 요청 시 `INSERT ... ON CONFLICT ... WHERE ... RETURNING`으로 원자적으로 횟수를 확보합니다. 원본 URL·실제 IP·API 키는 D1에 저장하지 않습니다.
- 모든 Gemini 키가 실패하면 추가 전역 잠금 없이 비AI 풀이를 제공합니다. 그날 해당 브라우저 식별값이 이 상황을 겪었다면 **다음 날의 한도에 전날 성공 호출 수의 절반(내림)**을 추가합니다. 예: 하루 한도 6회 중 4회 사용 후 키 전체 불가 → 다음 날 기본 6+2회. 서비스 불가로 실패한 호출은 사용량에서 차감하지 않습니다. 다음 날로 보너스가 이월되는 것은 하루뿐입니다.
- 동일 문장에 대한 병렬 호출은 D1 잠금으로 중복 모델 호출을 줄입니다. 캐시가 조회되지 않거나 D1 연결이 없다면 비용 방지를 위해 **AI를 호출하지 않고** 비AI 풀이를 반환합니다.
- 변환한 문장 부분을 드래그/선택한 뒤 **뜻 찾기**를 누르면 `/api/dictionary?q=...`에서 네이버 사전 API를 먼저, 키가 있다면 공식 표준국어대사전을 시도합니다. 외부 서비스가 차단되거나 뜻이 없으면 문맥상의 기본 풀이를 제공할 수 있습니다. 비공식 네이버 API는 변경될 수 있습니다.
- Gemini에는 **변환된 문장만 전송**하며 대상 URL/쿼리스트링/토큰을 보내지 않습니다. 단어 뜻 API에는 선택한 글자만 전송합니다. API 키와 IP의 원문을 기록하지 않습니다.
- 운영 규모에 따라 D1 및 Gemini 서비스의 읽기/쓰기·요청 한도가 적용될 수 있습니다. Cloudflare가 자동으로 D1 데이터베이스를 만들어 주지는 않으므로 위 설정이 필요합니다.

## v5 — 수동 AI 뜻풀이, 기기 구분, Gemini 장애 복구 (2026-10)

- **링크를 만들 때는 AI를 호출하지 않습니다.** 기본 설명은 단어·표현에 따라 달라지는 규칙 기반 풀이입니다. 사용자가 **AI 뜻풀이**를 누른 경우에만 Gemini를 요청합니다.
- AI 버튼 옆에 기기별 하루 사용 가능 횟수를 보여 주고 0회면 버튼이 비활성화됩니다. 캐시된 AI 풀이도 버튼을 눌렀을 때만 나타납니다.
- 생성 문장에서 단어를 드래그/선택하면 뜻 검색이 가능하다는 안내 문구를 표시합니다.
- 오래된 `api_state` 전역 5분 차단은 **완전히 사용하지 않습니다.** API 실패 이유는 `model_unavailable`, `rate_limited`, `key_rejected`, `invalid_response` 등으로 구분합니다. 여러 키를 모두 시도하며 과거 `gemini-2.5-flash-lite` 모델이 HTTP 404로 거부되는 경우 `gemini-3.5-flash-lite`를 재시도합니다.
- 신규 프로젝트는 `GEMINI_MODEL=gemini-3.5-flash-lite`를 권장합니다. Google의 무료 티어/할당량은 계정별 정책에 따라 달라집니다.
- **기존 D1 사용자 필수 작업:** `migrations/0002_device_usage.sql`을 운영 `MEANING_DB`에 한 번 적용합니다. 원래의 `daily_usage` 및 `api_state`는 호환을 위해 남겨 두되 더 이상 사용하지 않습니다. 새로운 `device_usage` 테이블이 없으면 `database_schema_error`로 AI가 비활성화됩니다.
- 신규 환경변수는 `GEMINI_DAILY_PER_DEVICE`와 `FINGERPRINT_HASH_SALT`입니다. 전환 중에는 기존의 `GEMINI_DAILY_PER_IP`, `IP_HASH_SALT` 값도 설정돼 있으면 사용할 수 있습니다. **IP는 횟수 제한에 사용하지 않습니다.**
- 기기 지문은 웹사이트가 생성한 **브라우저별 무작위 설치 ID**에 User-Agent·언어·시간대·화면 크기 등 비민감 브라우저 특성을 더해 브라우저에서 SHA-256 해시한 것입니다. 서버는 이 해시를 비밀 salt로 다시 해시해 D1에 저장합니다. 원본 IP, 식별 특성 및 URL은 저장하지 않습니다. 이 방식은 브라우저 프로필 단위의 **가명 식별**이며 실제 물리적 기기를 완벽히 구별하지 못합니다. 사이트 데이터 삭제/시크릿 모드/위조 시 새 식별값이 만들어질 수 있습니다. 운영 사이트에는 이 사실을 개인정보 안내에 포함해 주세요.
- DB에는 원본 URL을 저장하지 않고 동일 한글 문장 해시를 통한 뜻풀이 결과만 캐시합니다. API 키 전부 실패하면 사용 횟수를 돌려주고 다음 날 이전 성공 사용 횟수 절반을 보너스로 제공합니다. **키를 전역 차단하지 않으므로 이후 요청은 다시 시도 가능합니다.**
